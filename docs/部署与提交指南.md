# 部署与提交操作手册

> 站点：https://zhuluzhisen.github.io
> 仓库：https://github.com/zhuluzhisen/zhuluzhisen.github.io
> 技术栈：Astro 7 + Tailwind 4，托管在 GitHub Pages

---

## 一、先记住这一句

**本地改完 → `git push` → 等 2 分钟 → 线上自动更新。**

不需要手动上传、不需要手动打包。`dist/` 是构建产物，已在 `.gitignore` 里，**永远不要提交**。GitHub Actions 会在云端重新构建并发布。

---

## 二、日常工作流（三行命令）

打开 Git Bash，进项目目录：

```bash
cd "C:/Users/Administrator/WorkBuddy/个人博客"

git add -A                                   # 暂存所有改动
git commit -m "feat: 这里写你改了什么"        # 提交
git push                                     # 推送，自动触发部署
```

推送成功后，浏览器打开仓库的 **Actions** 标签页，能看到一条 `Deploy to GitHub Pages` 在跑，绿色勾 = 上线成功。

---

## 三、更稳妥的四步法（推荐）

`git add -A` 图省事，但容易把临时文件、备份文件一起提交。想稳一点就按下面走：

### 第 1 步：看改了什么

```bash
git status          # 列出改动文件
git diff            # 看具体改了哪几行
git diff --stat     # 只看改动规模
```

### 第 2 步：按类别暂存

```bash
git add src/pages/xxx.astro          # 暂存单个文件
git add src/pages/games/             # 暂存整个目录
git add -A                           # 或者全部暂存
```

### 第 3 步：写提交信息

```bash
git commit -m "feat: 新增游戏厅四个小游戏"
```

多行说明用这个写法（第一条双引号，结尾引号**顶格**）：

```bash
git commit -m "fix: 修复移动端横向溢出

- 首页 hero 区宽度改为 100%
- 相册网格在小屏改为两列"
```

### 第 4 步：推送

```bash
git push
```

---

## 四、提交信息怎么写

仓库现有历史是 `feat:` / `fix:` 前缀风格，保持一致就行：

| 前缀 | 什么时候用 | 例子 |
|---|---|---|
| `feat:` | 新增功能、新页面、新游戏 | `feat: 新增游戏厅，四款 Canvas 小游戏` |
| `fix:` | 修 bug、修样式错位 | `fix: 修复浅色主题遮罩标题对比度` |
| `style:` | 纯样式调整，不改逻辑 | `style: 页头导航间距收紧` |
| `docs:` | 只改文档 | `docs: 补充部署说明` |
| `chore:` | 依赖、配置、脚本 | `chore: 升级 astro 到 7.4.4` |

一条 commit 只做一件事。**改功能**和**改站名**这种互不相关的改动，拆成两个 commit 分开提交，出问题时好回滚。

## 五、本地预览（推之前先看一眼）

### 开发模式（改代码自动刷新）

```bash
cd "C:/Users/Administrator/WorkBuddy/个人博客"
PATH="$PWD/.tools/node:$PATH" ./node_modules/.bin/astro dev
```

打开 http://localhost:4321 ，改文件浏览器会自动刷新。按 `Ctrl+C` 停止。

### 构建产物预览（最接近线上效果）

```bash
PATH="$PWD/.tools/node:$PATH" ./node_modules/.bin/astro build
PATH="$PWD/.tools/node:$PATH" ./node_modules/.bin/astro preview
```

> **重要坑位**：系统自带的 Node 是 v22.22.2，低于 Astro 7 要求的 `>=22.23.4`，直接 `npm run build` 会报错：
> `Node.js v22.22.2 is not supported by Astro!`
> 项目里自带了合规版本在 `.tools/node/node.exe`，所以命令前面要加 `PATH="$PWD/.tools/node:$PATH"`。
> 这只影响本地，**GitHub Actions 用云端 Node 22.x，不受影响**。

## 六、查看部署状态

### 方式一：网页（最直观）

打开 https://github.com/zhuluzhisen/zhuluzhisen.github.io/actions

- 黄点 = 构建中（约 1~2 分钟）
- 绿勾 = 成功，已上线
- 红叉 = 失败，点进去看哪一步红，展开日志找 `Error`

### 方式二：命令行查 API

```bash
curl -s "https://api.github.com/repos/zhuluzhisen/zhuluzhisen.github.io/actions/runs?per_page=1" \
  | grep -E '"(status|conclusion)"' | head -2
```

`"status": "completed"` + `"conclusion": "success"` = 完成。

### 方式三：直接验线上

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://zhuluzhisen.github.io/games/
```

返回 `200` 即页面存在。

### 手动触发部署（没改代码也想重新发布）

Actions 页面 → 左侧 `Deploy to GitHub Pages` → 右侧 **Run workflow** → 选 `master` → 运行。
（工作流里配了 `workflow_dispatch`，所以支持手动触发。）

## 七、上线后页面没变化？

按顺序排查：

1. **强刷缓存**：`Ctrl + F5`（或 `Ctrl + Shift + R`）。GitHub Pages 有 CDN 缓存，普通刷新可能读到旧页。
2. **确认 Actions 成功**：绿勾才算发布完成，黄点还在跑就再等等。
3. **确认 commit 真的推上去了**：`git log origin/master --oneline -3`，看最新 commit 在不在。
4. **无痕窗口验证**：排除本地缓存和 Service Worker 干扰。
5. 以上都对还不对 —— 检查是不是访问了错误路径（比如 `/games` 少了结尾斜杠，虽然能跳转，但某些子资源可能 404）。

## 八、出问题了怎么退

### 推错了想撤回（还没推）

```bash
git reset --soft HEAD~1     # 撤销最近一次提交，改动保留在暂存区
```

### 已经推上去了

优先用 revert（安全，留下记录，不会破坏别人/其他地方的历史）：

```bash
git log --oneline -5              # 找到要撤销的 commit 哈希
git revert <commit哈希>           # 生成一个反向提交
git push                          # 推送，线上回滚
```

### 只是想让线上重跑一次

Actions 页面 → 对应那条运行 → 右上 **Re-run all jobs**。

## 九、push 被拒怎么办

如果报 `! [rejected] ... (fetch first)` 或 `non-fast-forward`，说明远端有你本地没有的提交（常见于在网页上直接改过文件）：

```bash
git pull --rebase origin master    # 把远端提交拉下来，你的提交叠在上面
git push
```

冲突了会停下来提示，手动改完冲突文件后：

```bash
git add <冲突文件>
git rebase --continue
```

想放弃这次 rebase：`git rebase --abort`。

## 十、首次在新电脑上配置（换机器才需要）

```bash
# 1. 克隆仓库
git clone https://github.com/zhuluzhisen/zhuluzhisen.github.io.git
cd zhuluzhisen.github.io

# 2. 装依赖
npm ci

# 3. 配置身份（只需一次，全局）
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"

# 4. 如果 push 要密码，用 GitHub 的 Personal Access Token 当密码
#    Settings → Developer settings → Personal access tokens → 勾选 repo 权限
```

> 仓库根目录需要放一份合规的 Node（`.tools/node`），或者本机装 Node ≥ 22.23.4，否则本地构建会报版本错误。

## 十二、常用命令速查

| 目的 | 命令 |
|---|---|
| 看状态 | `git status` |
| 看改动 | `git diff` |
| 看最近提交 | `git log --oneline -5` |
| 看远端最新 | `git log origin/master --oneline -3` |
| 暂存全部 | `git add -A` |
| 提交 | `git commit -m "说明"` |
| 推送（自动部署） | `git push` |
| 撤销未推送的提交 | `git reset --soft HEAD~1` |
| 回滚已推送的提交 | `git revert <hash>` && `git push` |
| 拉取远端更新 | `git pull --rebase origin master` |
| 本地开发预览 | `PATH="$PWD/.tools/node:$PATH" ./node_modules/.bin/astro dev` |
| 本地构建 | `PATH="$PWD/.tools/node:$PATH" ./node_modules/.bin/astro build` |
